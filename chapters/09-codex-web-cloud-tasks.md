# 第九章：Codex Web 与云端任务

你在网页上提交一个任务，然后关掉电脑。过一段时间回来，Codex 已经读取仓库、修改文件、运行检查并给出差异。这种体验很像“远程使用自己的电脑”，但实际并不是。

Codex 云端任务运行在 OpenAI 托管的隔离环境中。它会检出你指定的仓库版本，按照环境配置准备依赖，在容器中执行，再把结果和差异交还给你。理解这一点，才能正确提供材料、配置网络和判断为什么云端看不到本地修改。

## 9.1 先区分网页 Work 与 Codex 云端

ChatGPT 网页可以承载多种在线工作。

**Chat 与 Work**可以使用上传文件、项目来源、插件和获准工具，适合研究、报告、表格、演示及持续工作。它们不直接操作你电脑上的文件夹。

**Codex 云端任务**则面向连接的代码仓库和托管执行环境，适合分析项目、准备变更、运行检查和并行处理独立任务。它会在隔离容器中工作，并返回文件 diff。

两者都在网页发起，但材料和运行方式不同。报告任务没有必要先建代码仓库；需要修改仓库的任务，也不应只上传几个零散文件后期待它理解完整项目。

## 9.2 云端任务实际怎样运行

提交任务后，当前官方流程大致是：

1. 创建隔离容器，检出所选仓库的分支或 commit SHA；
2. 运行 setup script；若恢复缓存环境，可再运行 maintenance script；
3. 应用网络访问设置；
4. 智能体读取项目、运行命令、修改文件并验证；
5. 返回回答与文件差异，你可以继续追问或进入 PR 流程。

默认环境镜像名为 `universal`，预装常见语言、包和工具。它只是方便起点，不保证包含项目所有依赖。项目需要的版本、服务和构建步骤仍应通过环境配置说明。

容器隔离意味着云端任务不会直接覆盖你电脑上的当前目录，也不会继承个人浏览器登录或桌面应用状态。这是安全和可复现优势，同时也是重要边界。

## 9.3 连接仓库之前要检查什么

云端 Codex 需要访问代码仓库。授权 GitHub 或其他受支持来源时，使用最小仓库范围，不要因为一次任务开放整个组织。组织工作区还可能要求管理员批准连接和仓库访问。

选择任务时确认：

- 仓库是否正确，是否包含所需子模块或大文件；
- 基础分支和 commit 是否是预期版本；
- 未提交的本地修改是否已经安全记录；
- 项目规则、测试和 setup script 是否进入仓库；
- 任务结果应提交到哪个分支或只返回 diff。

云端只能看到已进入可访问仓库的内容。你本机尚未提交的“最新修改”、被忽略的本地配置和桌面文件都不会自动出现。若这些材料是任务必要输入，应以安全方式提交、上传样例或配置环境，而不是在提示中假设它们存在。

## 9.4 配置云端环境

环境决定云端任务能否真正运行项目。常见包管理器可以自动安装依赖；复杂项目则应提供自定义 setup script。需要特定 Python、Node.js 或其他运行时版本时，应固定版本，避免依赖镜像当前默认。

setup script 用于安装工具和依赖，不应承担每次任务的业务逻辑。它在与智能体不同的 Bash 会话中运行，临时 `export` 的变量不会自然延续到代理阶段。需要全程可用的普通变量，应在环境设置或合适启动文件中配置。

setup script 应可重复运行、失败时给出清楚错误，并尽量减少无关下载。先在干净环境或本地容器中测试，避免每个云端任务都花很长时间试错。

如果仓库包含 `AGENTS.md`，云端 Codex 可以从中获得项目运行、测试与检查方式。规则必须与云端环境一致，不要写只在某位成员电脑上存在的绝对路径。

## 9.5 环境变量与 Secret

普通环境变量在 setup 和智能体执行阶段都可以使用。Secret 则会加密保存，只在任务执行时解密，并且出于安全原因只提供给 setup script；进入智能体阶段前会移除。

这意味着不能假设智能体可以直接读取数据库密码或部署密钥。若任务必须访问外部服务，应重新审视是否真的需要、能否使用只读测试账号，以及怎样避免凭证进入日志和模型上下文。

不要把 Secret 写进仓库、`AGENTS.md`、setup 输出或提示。设置脚本也不应 `echo` 敏感值。凭证要有最小权限、独立环境和可撤销性；任务结束后检查是否仍需保留。

## 9.6 网络访问分为两个阶段

云端环境的 setup 阶段可以联网安装依赖。智能体实际执行阶段默认关闭互联网，可以按需配置有限或不受限访问。所有外部流量会经过代理。

需要网络时，优先只开放必要域名和用途。例如测试只调用一个沙箱 API，就不必允许任意互联网。实时研究任务应记录来源和日期，并防范网页提示注入。

网络关闭导致下载或测试失败时，不应让 Codex 编造成功结果。它应该报告哪个请求被阻止；你再决定修改环境、提供离线依赖，还是把该步骤留在本地。

## 9.7 缓存加速与版本一致性

Codex 可以缓存云端容器状态最长约 12 小时，缩短新任务和后续任务的环境准备时间。修改 setup script、maintenance script、环境变量或 Secret 会使缓存失效。

缓存不是项目版本。恢复缓存时仍会检出任务指定分支，但先前安装的依赖可能来自较旧提交。maintenance script 可以在恢复时更新依赖；环境明显不兼容时，应重置缓存。

不要因为第二次任务启动更快，就假设它与第一次拥有相同代码和数据。每次仍要记录基础提交、数据截止时间和环境版本。

## 9.8 怎样写云端任务

云端任务尤其需要明确仓库范围、变更边界和验证命令。例如：

> 在仓库 `docs-site` 的当前主分支基础上，检查内部 Markdown 链接。只修复能够由仓库文件证明的相对路径错误，不改正文措辞，不升级依赖。运行现有链接检查和格式检查；完成后提供修改文件列表、失败链接和 diff。不要创建 PR，先让我审查。

与本地任务相比，还应说明：任务针对哪个分支或提交；是否允许网络；环境设置是否已经准备；最终只返回分析、生成 diff，还是可以创建 PR。

一次任务只处理一个可审查结果。不要同时要求架构重写、依赖升级、文档重构和生产发布。云端可以运行很久，但长时间不等于范围可以无限扩大。

## 9.9 检查云端结果

完成后至少查看四项：

1. **回答**：它声称完成了什么，有哪些限制；
2. **diff**：实际改了哪些文件和行；
3. **验证**：运行了哪些命令，是否真的成功；
4. **基础版本**：结果建立在哪个分支或提交之上。

你可以继续在同一云端任务中追问、要求修复或缩小范围，也可以创建 PR 供团队审查。CLI 还提供把最近云端 diff 应用到本地工作树的能力，但应用前必须确认本地状态和冲突。

不要看到绿色摘要就直接合并。云端环境的测试可能缺少真实服务、浏览器或生产数据；未验证项应明确进入 PR 说明。

## 9.10 并行云端任务的边界

多个独立云端任务可以同时调查不同问题，减少等待。但两个任务同时修改相同文件、接口或分支，会增加冲突。

并行前按文件、模块或结果划分所有权；尽量让探索任务只读，让修改任务作用于不同范围。每个任务使用清楚基础提交，最终由一个主任务或负责人合并并运行整体检查。

云端隔离解决的是执行环境，不会自动协调方案。两个任务各自测试通过，合并后仍可能失败。

## 9.11 安全与账号要求

云端任务直接接触代码仓库，应使用多因素认证、最小仓库授权和组织批准的账号。不要连接自己无权交给第三方处理的仓库或数据。

检查 setup script 与仓库配置是否来自可信来源。恶意项目可能在安装阶段运行命令、读取可用环境或尝试传出数据。Secret 只在设置阶段可见降低了风险，但并不意味着可以把高权限生产凭证交给未知脚本。

任务需要创建 PR、修改外部状态或触发部署时，应保留人工确认。云端执行方便，不会取消团队保护分支、代码审查和发布审批。

## 9.12 常见故障

**云端看不到最新修改。** 本地变化尚未提交，或任务选择了错误分支和 SHA。

**依赖安装失败。** 检查 setup script、运行时版本、私有包认证和网络。

**设置阶段有变量，执行时没有。** 普通变量未持久配置，或使用的是只提供给 setup 的 Secret。

**测试需要网络但请求被阻止。** 智能体阶段默认关闭互联网，应按最小范围配置。

**缓存后出现奇怪错误。** 仓库与缓存依赖不兼容，运行 maintenance 或重置缓存。

**结果无法直接合并。** 基础分支已经变化，或并行任务修改相同区域，需要重新同步与审查。

## 9.13 第一次云端实践

选择一个无敏感信息的测试仓库，先做只读任务：

> 在当前分支只读检查项目。说明检出的 commit、主要目录、setup 结果、可用测试和网络状态。不要修改文件。运行一个成本最低的现有检查，并报告命令、退出状态和未满足依赖。

确认环境正确后，再要求修改一处低风险文档并返回 diff，不创建 PR。验收时对比基础提交、文件范围和检查输出。只有这条链路稳定后，才增加 Secret、外部网络或自动创建 PR。

## 9.14 本章小结

网页 Work 使用上传与连接来源完成在线工作；Codex 云端任务则在隔离容器中检出仓库、准备环境、执行修改并返回 diff。云端不会自动看到本机状态，环境、变量、Secret、网络和缓存都需要明确配置。

> 使用云端的关键不是“把电脑搬上去”，而是让任务在一个可重建、可隔离、可审查的环境中运行。

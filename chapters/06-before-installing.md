# 第六章：安装前准备

很多人第一次使用 Codex，会先安装所有客户端、扩展和插件，然后才想“我到底要让它做什么”。结果往往是入口很多、权限提示很多，真正任务却没有准备好。

安装前最重要的不是下载速度，而是选择一个合适入口，准备一项安全的首次任务，并明确材料、账号与验收。做好这些工作，安装完成后就能立刻验证环境，而不是在空白输入框前继续摸索。

> 不要先搭建最复杂的环境；先准备一条能够跑通的最小工作链。

## 6.1 先决定第一项真实任务

一个好的首次任务应当低风险、范围小、容易检查，并能体现 Codex 与普通问答的区别。例如：读取三份资料副本，生成一份带来源的比较摘要；检查一个练习项目的文件结构；给静态网页修改一段文案并提供差异。

不要把首次任务设成“重构整个项目”“整理全部网盘”“自动发送客户邮件”或“接管日常工作”。环境、权限和任务方法都尚未验证时，范围越大，越难判断问题出在哪里。

首次任务可以写成四行：

- **材料**：使用哪些文件或项目；
- **成果**：最后要得到什么；
- **边界**：不能修改、发送或访问什么；
- **验收**：怎样证明完成。

例如：

> 阅读练习文件夹中的三份会议记录副本，生成一份 Markdown 摘要，分为决定、待办、风险和未知项；每项注明来源文件。不要修改原文件，不要联网，不要发送任何内容。完成后列出实际读取的文件，并检查是否遗漏。

这项任务既能测试文件访问和生成能力，也不会带来难以恢复的后果。

## 6.2 根据任务选择入口

第二步不是安装全部产品，而是选择第一入口。

如果材料已经在线，只需要研究、报告、表格或演示，从 ChatGPT 网页的 Chat 或 Work 开始最简单。材料主要在本机，需要打开文件夹、生成本地成果或使用桌面工具时，选择 ChatGPT 桌面应用。工作发生在终端或代码仓库中，才考虑 Codex CLI；日常围绕编辑器工作，则选择 IDE Extension。

云端任务适合已经连接仓库、可以在隔离环境运行的工作，不是读取个人电脑文件的捷径。Sites 则用于最终要托管和分享网站的情况。

入门阶段只需一个主要入口和一个备选。以后发现真实瓶颈，再增加插件、CLI、IDE 或云端环境。避免为了“功能齐全”一次配置所有表面。

## 6.3 检查账号与可用范围

Codex 的入口、模型、额度和功能会受到 ChatGPT 方案、地区、设备与工作区策略影响。安装前先登录 ChatGPT，确认自己使用的是个人工作区还是组织工作区，并查看当前界面实际提供的入口。

本地 Codex 可以使用 ChatGPT 账号或 API key 登录；Codex cloud 要求使用 ChatGPT 登录。两种认证对应不同权限、计费和数据控制：ChatGPT 登录遵循相应工作区与方案，API key 登录遵循 OpenAI Platform 组织和项目。

普通使用者优先沿用 ChatGPT 登录即可。API key 更适合程序化 CLI、CI/CD 或独立 API 计费，不是使用 Codex 的必备条件。不要为了跳过方案限制而随意创建和暴露 key。

组织账号还可能受到管理员设置影响，例如是否允许本地 Codex、云端任务、插件、特定模型或外部连接。看不到功能时，先核对方案与工作区政策，不要反复重装。

## 6.4 检查设备与系统环境

网页入口只需要受支持浏览器和稳定网络。桌面应用当前主要面向 macOS 与 Windows，具体系统要求和下载方式应以官方安装页为准。Windows 11 是当前官方推荐基线；较新的 Windows 10 可能以 best effort 方式工作。Linux 用户可以使用 Codex CLI、IDE Extension 和网页能力，但不要假设桌面应用与其他平台完全相同。

CLI 需要可用的终端和安装方式，项目工作通常还需要 Git。不同语言项目可能依赖 Node.js、Python、Java 或其他运行环境，但这些不是 Codex 本身对所有人的统一要求。只安装第一项任务真正需要的工具。

在企业设备上，软件安装、浏览器扩展、屏幕录制、辅助功能、代理和终端执行可能受管理策略限制。提前确认，不要通过关闭系统安全控制来绕过组织要求。

## 6.5 准备一个安全工作区

第一次本地实践，创建一个专门文件夹，只放无敏感信息的资料副本。不要直接打开整个用户主目录、云盘根目录或包含客户资料的共享目录。

推荐的练习结构可以很简单：

```text
codex-practice/
├── sources/        原始资料副本
├── output/         Codex 生成的成果
└── README.md       任务目标与检查方法
```

把原始材料与输出分开，可以更容易判断 Codex 改了什么。文件名应具有含义，并明确日期或版本，例如 `访谈-2026-07-15.md`，不要同时保留多个都叫“最终版”的文件。

若任务会修改项目，优先使用 Git 或至少建立备份。Git 能记录文件变化，但不能恢复未被版本管理的外部数据，也不能撤回已发送消息。对于非 Git 文件，保留只读原件与独立副本。

## 6.6 清理敏感信息

安装前检查练习目录和项目中是否存在：

- `.env`、API key、token、私钥和密码；
- 真实客户、患者、员工或学生信息；
- 身份证件、支付资料和内部财务信息；
- 私人通信、浏览记录和未公开合同；
- 生产数据库导出或可直接操作生产系统的凭证。

不需要的数据不要交给任务。需要字段结构时，可以使用脱敏样例；需要测试登录时，使用专门测试账号。把文件加入 `.gitignore` 只能防止普通 Git 提交，不等于阻止智能体读取；真正敏感路径应从工作区移除或通过权限明确拒绝。

使用 API key 时，不要把它写进提示、脚本示例、截图或仓库。使用产品支持的登录流程、环境变量或凭证存储，并了解其数据政策属于 ChatGPT 工作区还是 API 组织。

## 6.7 规划权限，而不是遇到再全开

本地权限包含两个问题：沙箱允许 Codex 访问什么，审批决定跨越边界时由谁确认。初次使用应选择 **Ask for approval**，把工作区限制在练习目录。

只读分析不需要写入整个项目；本地文件任务不一定需要公网；生成草稿不需要邮件发送权限。提前写下本次任务真正需要的权限：读取 `sources/`，写入 `output/`，不访问网络，不使用外部应用。

当工具申请超出范围时，先看它为什么需要，而不是机械同意。批准一次比永久放行更适合试用。Full access 会移除重要边界，不应成为“避免弹窗”的默认设置。

## 6.8 检查网络与组织限制

登录、下载和云端任务需要网络；本地命令的网络访问则可能由沙箱关闭。公司代理、防火墙、VPN、证书和域名限制可能影响认证、依赖安装或网页工具。

不要把“浏览器能打开 ChatGPT”理解成“所有 Codex 工具都能访问互联网”。网页搜索、Browser、插件、本地终端和云端代理的网络控制彼此不同。出现问题时记录是哪个入口、哪个步骤和哪个域名失败。

如果项目依赖私有包、内部 Git 或企业服务，应在管理员批准的方式下配置。不要将内部凭证复制到公开提示来临时绕过认证。

## 6.9 先确定验收与恢复方法

安装成功不只是应用能够启动。至少要验证：

1. 登录的是正确账号和工作区；
2. Codex 只看到你选择的项目或资料；
3. 权限模式符合预期；
4. 能读取指定文件；
5. 能在指定位置创建一个成果；
6. 你能查看修改或恢复练习副本；
7. 退出再打开后，项目和任务状态合理。

把这些标准写进 `README.md`，安装后按顺序测试。如果某一步失败，就能定位到认证、文件、权限、工具或应用本身，而不是笼统地说“Codex 不能用”。

## 6.10 安装前检查表

开始下载之前，确认下面各项：

- [ ] 我有一项低风险、可检查的首次任务；
- [ ] 我知道第一入口是网页、桌面、CLI 还是 IDE；
- [ ] 我确认了账号、工作区和可用方案；
- [ ] 设备与系统满足当前官方要求；
- [ ] 练习材料是副本，并已移除敏感信息；
- [ ] 工作目录范围清楚，不是整个个人目录；
- [ ] 修改前有 Git 记录或其他备份；
- [ ] 我知道本次任务需要哪些文件与网络权限；
- [ ] 我写下了验收和恢复方法；
- [ ] 组织设备和账号允许安装与使用。

没有全部满足也不意味着不能开始。例如只使用网页 Chat 时不需要 Git。但凡与本次入口相关的项目，都应在安装前确认。

## 6.11 一个可复制的准备任务

你可以先在普通 Chat 中完成环境设计：

> 我准备第一次使用 Codex。任务是读取三份非敏感会议记录副本，生成一份带来源的摘要，不修改原文件、不联网。请根据材料位置、操作系统和最终成果，建议一个最小入口；列出需要准备的文件结构、权限、验收步骤和失败后的恢复方法。不要建议安装与本任务无关的工具。

预期成果是一张具体准备清单，而不是泛泛的安装教程。检查建议是否与真实设备、资料位置和工作区相符，再进入下一章安装桌面应用。

## 6.12 本章小结

安装 Codex 之前，先准备任务、入口、账号、设备、材料、权限、验收和恢复方法。从无敏感信息的副本开始，只安装第一条工作链所需的工具。

> 安装的完成标准，不是图标出现在桌面，而是一个低风险任务能在正确边界内被执行和检查。

下一章将进入 ChatGPT 桌面应用，完成登录、项目选择和第一次本地 Codex 任务。

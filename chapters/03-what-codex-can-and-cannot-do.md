# 第三章：Codex 能做什么，不能做什么

假设你面前有十二份访谈、一张调查表、五个产品网址，以及一份明天要汇报的空白文档。你需要的不是再听一遍“应该怎样调研”，而是有人读完材料、核对信息并交出可以审阅的报告。

人们对 Codex 常有两种误解：只把它当成生成答案的聊天工具，或者把它想成无所不能的数字员工。前者浪费了行动能力，后者则忽略了它会误解、会犯错，也受工具和权限限制。

在本书所说的 Codex 工作生态中，它最擅长的事情可以概括成一句话：

> 进入一个具体的工作环境，理解已有材料，围绕明确目标调用工具、执行步骤，并把结果推进到可以检查和使用的状态。

关键词是**环境、材料、目标、行动和检查**。少了任何一个，可靠性都会下降。

## 3.1 它不只是回答，而是行动

普通聊天工具给出答案，后续通常由人执行。Codex 更像能够进入现场的协作者：获得权限后，它可以读取文件、寻找资料、制定计划、修改内容、运行命令、检查输出，并根据真实结果继续调整。

例如，聊天回答可能告诉你如何给访谈分类；智能体则可以直接阅读材料、建立分类、生成比较表，再保存为可修改的文档。差别不是谁说得更像专家，而是有没有接触工作对象并把任务向前推进。

## 3.2 先分清 Codex 与周边能力

严格来说，**Codex 是以软件开发和项目执行为核心的智能体**。Chat 更适合问答与讨论，Work 面向报告、分析、表格和演示等日常工作，Sites 面向网站创建与发布；Browser 和 Computer Use 则是访问网页、操作图形界面的工具。

它们可以协同工作，也经常出现在同一个任务里。例如，一份市场研究更适合从 Work 开始，过程中使用 Browser 查找资料；修改软件项目更适合进入 Codex，再用浏览器检查页面；需要快速制作并发布网站时，可以使用 Sites。

为了方便叙述，本书会用“**Codex 工作生态**”指代 Codex 及其相邻的工作能力；当“Codex”单独出现时，则优先指 Codex 智能体本身。下一章会专门比较这些入口，本章只先记住一条：**入口决定工作方式，工具决定它能接触什么。**

## 3.3 Codex 能做的五类事情

### 一、读取和理解

Codex 工作生态可以从已有材料开始，而不是只能凭空生成内容。在获得相应访问权限后，它可以帮助你：

- 阅读会议记录、研究资料、合同草稿或政策文件；
- 分析表格的字段、缺失值、异常值和基本关系；
- 在大量文件中寻找同一主题、人物或决策；
- 比较文档、方案或项目版本之间的变化；
- 从日志、截图、错误信息和用户反馈中寻找线索；
- 结合本地文件、网页和已连接的数据源建立上下文。

这类任务通常是很好的起点，因为它们不急着改变任何东西。你可以先让 Codex 列出读到了哪些材料、怎样理解任务、还有哪些信息缺失，再判断它是否找对了方向。

### 二、创建和修改

当目标和边界足够清楚时，它可以直接创建或修改成果，例如：

- 把访谈、会议或研究材料整理成报告；
- 清洗数据并制作比较表格；
- 把已有内容转化为演示文稿；
- 生成图片、网页、网站原型或简单工具；
- 编写项目文档、脚本和代码；
- 按照反馈修改已有文件，而不是每次从零开始。

日常办公成果通常更适合在 Work 中完成，软件项目则更适合交给 Codex。但无论使用哪个入口，“已经生成”都不等于“已经正确”。创建只是中间步骤，后面还要检查内容和实际文件。

### 三、调用工具和执行步骤

Codex 与普通文本生成工具的明显区别，是它可以在获得权限后使用工具。

例如，它可以：

- 搜索文件和内容；
- 运行计算、程序、测试和检查命令；
- 通过 Browser 查找资料或完成网页中的步骤；
- 通过插件读取网盘、邮件、日历或协作平台中的信息；
- 在命令行或结构化连接无法完成时，用 Computer Use 操作图形界面；
- 查看修改前后的差异，并根据结果继续调整；
- 把一个目标拆成多个步骤连续推进。

工具让 AI 从“给建议”变成“做事情”，也带来了新的风险。读取文件和删除文件不是一回事；起草邮件和真正发送邮件也不是一回事。越接近真实行动，越需要明确权限和确认点。有专用插件或结构化接口时，通常应优先使用；只有任务依赖可视界面时，再使用浏览器或 Computer Use。

### 四、检查和验证

可靠的智能体工作不应该停在“已经生成”。它还可以根据成果类型做不同检查，例如：

- 把报告中的关键结论追溯到来源；
- 核对表格行数、公式、总计和异常值；
- 打开演示文稿，检查是否有溢出、空白页或图表错误；
- 在浏览器中查看网页，检查链接、布局和交互；
- 对软件修改运行测试、查看差异并复现原问题；
- 按照你给出的验收清单逐项说明证据。

验证能力非常重要，因为大模型生成的内容表面上常常很完整，即使其中存在错误，也可能读起来十分流畅。

例如，一个更好的任务不是：

> 帮我把这个功能做完。

而是：

> 完成这个功能，运行相关检查，说明你验证了什么，并列出仍然无法确认的部分。

验证不会让错误完全消失，也不能由“它说自己检查过了”来代替证据。真正有用的验证会留下来源、检查结果、文件差异、截图或测试输出，让人能够复核。

### 五、持续和并行工作

对于较长的任务，可以先使用计划模式收集上下文、澄清问题和安排步骤，再根据需要使用目标、自动化或并行任务保持进度。这里的几个概念并不相同：计划模式负责“先想清楚”，目标负责在当前任务里持续追踪要完成的结果，自动化负责定期触发，子智能体或并行任务负责同时处理相互独立的工作。

这使它适合：

- 分阶段完成一个复杂研究或项目；
- 定期更新行业、产品或团队报告；
- 同时调查多个互不依赖的方向；
- 把重复工作固化为 Skill；
- 让稳定流程按计划自动运行。

但是，持续运行不等于完全无人监管。计划不是正确性的保证，目标也不会自动补齐缺失信息。第一次执行的新流程、涉及外部账号的任务，以及可能修改重要数据的操作，都应该保留人工检查。

## 3.4 什么样的任务最适合交给 Codex

判断一项任务是否适合交给 Codex，可以使用下面五个标准。

| 判断标准 | 需要回答的问题 |
| --- | --- |
| 目标明确 | 最后究竟要得到什么？ |
| 上下文充分 | Codex 是否拿到了必要的文件、资料和背景？ |
| 范围可控 | 它应该处理哪些内容，又不能碰哪些内容？ |
| 结果可验证 | 我们怎样判断它做对了？ |
| 失败可恢复 | 如果出错，能否撤销、重试或从备份恢复？ |

满足这些条件的任务，通常容易取得好结果。例如：

- 根据指定资料制作一份带来源的比较报告；
- 找出项目中的某个问题并提出最小修改方案；
- 把会议材料整理成纪要、待办和跟进草稿；
- 根据明确字段清洗一份表格；
- 创建一个简单网站并在浏览器中检查；
- 每周从固定来源生成一份变化摘要。

把这些标准写进任务时，可以压缩成四个部分：

> 使用哪些材料，完成什么成果，遵守哪些边界，怎样才算完成。

例如，不要只说“分析这些访谈”，而可以说：

> 阅读 `访谈记录` 文件夹中的全部材料，为产品团队制作一份不超过六页的研究摘要。区分共同问题、少数意见和相互矛盾的信息，每条关键结论标注来源文件。不要补写受访者没有表达的观点。完成后列出未能读取的文件和仍需人工确认的判断。

相反，如果连最终成果是什么都说不清，也不知道如何判断对错，那么把任务交给 Codex 并不会自动解决问题。它只会在不完整的信息上做更多推断。此时更适合先用 Chat 讨论目标，或进入计划模式澄清问题，而不是马上执行。

## 3.5 Codex 不能替你保证什么

### 一、不能保证所有事实都正确

大语言模型会根据当前上下文生成看起来最合适的内容，但表达流畅不等于已经经过事实核验。它可能误解材料、混淆时间、遗漏条件，甚至生成并不存在的来源。

涉及新闻、价格、政策、医学、法律、金融或其他会变化且影响重大的信息时，应要求它使用可靠来源，并由人进行交叉核对。

### 二、不能替你定义真正的目标

Codex 可以帮助你把模糊想法整理成计划，也可以通过提问澄清需求，但它无法替你决定什么才真正值得做。

“做一个更好的网站”“写一份有说服力的报告”“让产品更受欢迎”都不是完整目标。什么叫更好、说服谁、解决什么问题，仍然需要人来定义。

### 三、不能替你承担高风险决策

AI 可以整理证据、比较方案和提示风险，但不应该独立决定是否支付、签约、删除关键数据、公开敏感信息，或对医疗、法律和财务事项作出最终判断。

越是不可逆、影响范围大或涉及他人的行动，越应该由人确认。

### 四、不能突破权限和现实环境

没有获得访问权限的文件，Codex 不能读取；没有连接的账号，它不能凭空使用；被验证码阻止的网站，它未必能够继续；某些功能还会受到设备、地区、账号方案和组织设置的限制。

很多看似“AI 不够聪明”的问题，实际是工作环境没有配置好：打开了错误的文件夹、缺少工具、没有登录、权限不足，或者使用了不适合当前任务的入口。

### 五、不能保证长任务永远不跑偏

任务越长、材料越多、步骤越复杂，误解和偏离目标的机会就越多。计划模式、清晰的阶段成果和持续明确的目标可以减少问题，但不能彻底消除问题。

复杂任务应该设置检查点，而不是在开头说一句“全部做完再告诉我”。

### 六、不能替代你的责任

Codex 可以生成、修改和执行，但最终是否采用结果、是否对外发送、是否影响其他人，责任仍然属于使用者。

这是使用智能体最重要、也最容易被忽略的边界。

## 3.6 为什么 Codex 会犯错

Codex 犯错不一定是模型能力不足。目标含糊、关键材料缺失、版本错误、权限不足、外部内容过时、任务过大和验收标准没有说清，都会造成失败。

因此，改善结果不能只靠更换模型。补充必要上下文、缩小范围、先制定计划并明确完成标准，往往更加有效。

## 3.7 人和 Codex 应该怎样分工

一种实用的分工方式是：

| 人负责 | Codex 负责 |
| --- | --- |
| 决定真正目标 | 阅读和整理材料 |
| 提供关键背景 | 提出执行计划 |
| 设置权限和边界 | 完成重复或多步骤工作 |
| 判断风险是否可以接受 | 调用获准的工具 |
| 验收重要结果 | 提供检查结果和证据 |
| 对最终行动负责 | 根据反馈继续修改 |

这并不意味着人必须盯着每一步。恰当的做法是根据风险调整监督程度：低风险、可恢复的任务可以让 Codex 更自主；高风险、不可逆的任务则需要更多确认。

| 任务风险 | 典型例子 | 合适的监督方式 |
| --- | --- | --- |
| 低 | 阅读资料、起草提纲、分析副本 | 可以连续执行，结束后检查结果 |
| 中 | 修改文件、批量整理数据、发布测试页面 | 先限定范围，再检查差异和输出 |
| 高 | 对外发送、公开发布、付款、删除关键数据 | 在真正行动前由人明确确认 |

真正成熟的使用方式，不是把所有工作交给 AI，也不是每一步都由人亲自操作，而是找到适合当前任务的人机分工。

## 3.8 从安全的小任务开始

第一次使用时，不必从宏大的项目开始。准备一个只包含副本的练习文件夹，放入两三份文档或表格，然后使用下面的任务：

> 阅读当前文件夹中的资料，不要修改原文件。先列出你实际读到的文件和每份文件的主题，再生成一份综合摘要和一张比较表。所有关键结论都标注来源文件；无法确定的内容单独列出，不要自行补全。完成后检查是否遗漏文件，并说明你做过哪些核对。

这个练习同时包含了完整的智能体工作循环：读取材料、建立理解、创建成果、执行检查和报告不确定性。它的结果容易查看，出错容易发现，也不会影响原始资料。

完成以后，还可以逐步尝试以下任务：

1. 把一份长文档整理成结构化提纲；
2. 按照明确规则清理一份表格副本；
3. 根据几份指定资料制作一份短演示；
4. 创建一个简单网页并在浏览器中检查；
5. 让 Codex 先为一个复杂想法制定计划，但暂时不要执行。

当你逐渐理解 Codex 如何读取上下文、怎样申请权限、会在哪些地方做出假设之后，再把它用于更重要、更长期的工作。

## 3.9 本章小结

Codex 不是无所不知的专家，也不只是一个生成代码的按钮。它更像一个能够进入工作环境、使用材料和工具、持续推进任务的智能体。

它擅长读取、创建、执行、验证和持续推进，但这些能力需要几个前提：目标明确、上下文充分、范围可控、结果可验证、失败可恢复。

记住下面这条原则，就能避开许多常见问题：

> 可以让 Codex 多做，但不要让它在你无法检查的事情上独自做主。

下一章将进一步介绍 Chat、Work、Codex、Sites、Browser 等不同入口，帮助你为每一类任务选择合适的工作方式。

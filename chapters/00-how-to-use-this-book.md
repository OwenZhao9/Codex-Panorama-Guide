# 使用说明

《Codex 全景指南》不是一本按钮手册，也不是一本只教人生成代码的教程。它试图回答一个更基础的问题：当 AI 不再只是在对话框里给建议，而是能够读取材料、调用工具、修改文件并持续推进任务时，普通人应该怎样理解它、使用它和检查它？

本书从基础概念开始，逐步进入环境配置、核心能力、标准工作流和完整案例。你不需要预先掌握编程，也不必把每一章按顺序读完。更重要的是，带着一项真实但风险可控的任务，一边阅读，一边观察 Codex 如何理解上下文、请求权限、执行步骤和交付结果。

## 0.1 重要声明

### 这本书描述的是会变化的产品

Codex、ChatGPT、Work、Sites、模型、套餐、界面和使用限制都会更新。同一个功能也可能因设备、地区、账号方案、组织策略或灰度发布而不同。书中关于工作原理和方法的内容尽量保持稳定；模型名称、速度、价格、入口和可用范围等易变化信息，会注明核对日期。

当书中描述与当前产品界面不一致时，以 OpenAI 最新官方文档、界面提示和你的工作区政策为准。不要为了找到书中某个旧按钮，忽略产品已经给出的新路径或安全警告。

### AI 生成不等于事实成立

Codex 可以分析资料、生成文件、搜索网页和执行检查，但它仍可能误解需求、遗漏条件、使用旧信息或给出看似合理的错误结论。语言流畅、格式完整、任务显示“完成”，都不能单独证明结果正确。

重要数字、姓名、日期、引用和结论应回到来源核验。涉及医疗、法律、金融、安全或其他高风险事项时，应由具备相应资格的人作最终判断。本书提供的是通用使用方法，不构成这些领域的专业意见。

### 能执行意味着需要更多责任

聊天回答错了，影响可能停留在文字里；智能体操作错了，可能改变文件、发送消息、覆盖数据或公开内容。因此，本书反复强调最小权限、过程检查、可恢复性和人工确认。

在没有明确目标和恢复方案时，不要授权批量删除、付款、对外发布、发送重要信息或修改生产系统。第一次运行的新流程，应从只读材料、副本、测试账号或隔离环境开始。凡是会影响他人或难以撤销的行动，都应在真正执行前由人确认。

### 不要把敏感信息随手交给任务

任务只应获得完成工作所需的最少数据。上传文件、连接账号或开放本地目录前，检查其中是否包含密码、密钥、身份证明、客户资料、内部财务信息和他人的私人通信。不要在提示、示例、日志或公开仓库中写入 Secret、token 和真实敏感数据。

使用连接器、插件、MCP 或 Computer Use 时，还要理解数据会流向哪里、工具能读写什么、账号原有权限怎样生效。连接成功不代表适合把全部数据都交给它。

### 最终责任仍然属于使用者

Codex 可以提出方案、执行工作并提供证据，却不能替你决定真正目标、承担组织责任或取得他人同意。是否采用结果、是否对外发送、是否进入正式流程，最终由使用者和相关负责人决定。

本书不会把 Codex 描述成“永不犯错的数字员工”。更准确的理解是：它是一名行动能力很强、速度很快，但需要清楚任务、适当权限和实际验收的智能协作者。

## 0.2 这本书适合谁

本书面向所有希望把 AI 从“偶尔问问题”升级为“参与真实工作”的读者，尤其适合：

- 经常处理资料、研究、报告、表格和演示的人；
- 需要整理会议、项目、内容或团队信息的人；
- 希望制作网站、在线工具或自动化流程，但不一定会编程的人；
- 产品、运营、市场、设计、咨询、教育和创作者；
- 想了解 AI 智能体怎样工作、怎样授权和怎样验收的人；
- 希望用 Codex 理解、修改或管理软件项目的开发者。

你不需要具备编程基础。书中的代码、命令行和 Git 会被放在完整能力地图中解释，不会被当作所有读者的起点。遇到暂时用不到的技术内容，可以先理解它解决什么问题，再决定是否实践。

如果你只想寻找“万能提示词”，这本书可能不会给你期待的捷径。可靠结果通常来自目标、材料、边界和验收共同作用，不是来自某一句神奇指令。

如果你已经熟悉 Codex，也可以把本书当作体系化检查表：看看自己是否只在使用生成能力，却忽略了计划、来源、文件检查、权限、自动化和长期上下文。

## 0.3 阅读路线

全书分为基础认知、环境准备、核心功能、标准工作流、案例和附录。不同读者可以选择不同路线。

### 第一次接触 AI 智能体

建议从本说明开始，依次阅读第一篇和第二篇。先理解聊天机器人与智能体的差别、Codex 的能力边界、几种工作模式和使用入口，再安装或连接实际环境。这样可以避免一上来就被模型名称、命令和插件淹没。

完成环境准备后，先实践第 13 章 Work、第 19 章文件与网络研究，以及第 20 章文档、表格与演示。这条路线能最快建立“输入材料—完成任务—检查成果”的直觉。

### 以日常工作为主

优先阅读第 3、4、13、19、20、24、26 和 27 章。它们覆盖能力边界、模式选择、文件交付、外部连接、长期上下文和自动化。等遇到复杂任务时，再补读计划模式、目标模式和云端并行。

### 想制作网站或在线工具

先读第 3—5 章了解入口和边界，再读环境准备、第 22 章 Sites、第 23 章浏览器与 Computer Use，以及第 29 章 Git 与项目管理。不要把“页面已经生成”当成“产品已经可以公开使用”；发布前还要检查内容、权限、数据存储和真实交互。

### 以软件项目为主

可以快速浏览第一篇，然后重点阅读第二篇、第 14—18 章、第 23—29 章。开发者也不应跳过 Work、文件处理和文档章节，因为需求研究、发布说明、数据核验与协作同样属于软件交付。

### 把本书作为工具书

已经知道目标时，可以直接从目录进入相应章节。每章都尽量独立回答六个问题：它是什么、为什么有用、适合什么、不适合什么、怎样开始、怎样检查。章节末尾的实践任务可以直接复制，再根据自己的材料和边界修改。

阅读示例时，重点不是逐字照抄，而是辨认其中四种信息：使用哪些材料、要完成什么成果、必须遵守哪些限制、怎样证明完成。把这四项替换成自己的真实条件，比积累大量孤立提示词更有效。

## 0.4 版本与在线更新

本书当前产品信息以 **2026 年 7 月 18 日** 为核对基准。正文优先讲稳定方法；涉及模型、推理强度、Fast、套餐、平台支持和测试中功能时，会保留明确日期或成熟度说明。

在线版本发布在公开 GitHub 仓库：

- [Codex 全景指南](https://github.com/OwenZhao9/Codex-Panorama-Guide)

目录中的章节链接指向对应 Markdown 文件。Git 提交历史记录每次修改，便于查看某项说明何时加入或更新。发现错误、失效链接或产品变化时，可以通过仓库 Issue 提供：涉及章节、当前原文、你观察到的新情况，以及能够核验的官方来源。

在线更新遵循三条原则：

1. **稳定原理进入正文。** 例如任务定义、上下文、权限和验收，不因界面改版而频繁变化。
2. **动态信息标注日期。** 模型、价格、速度和可用范围不写成永久事实。
3. **重要能力优先引用官方资料。** 第三方经验可以帮助理解，但不能替代当前产品文档。

如果你阅读的是下载副本或打印版本，先查看在线仓库是否已有更新。尤其在照着模型配置、安装步骤、定时任务或发布流程操作前，应重新核对相关官方页面。

版本变化并不意味着旧内容全部失效。通常应该先区分：改变的是入口名称、界面位置，还是能力本身；是你的账号看不到，还是产品已经移除；是试验功能调整，还是稳定工作方法发生变化。带着这种判断阅读，比机械寻找完全相同的界面更可靠。

准备好以后，从第一章开始：先理解为什么今天的 AI 不再只是一个回答问题的聊天机器人。

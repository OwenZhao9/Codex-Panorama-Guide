# 第三十二章：质量检查与成果验收

Codex 交出一份格式漂亮的报告，引用齐全、图表清楚、结论也很有说服力。你随机打开一个来源，却发现关键数字来自不同年份；演示里的总计又与表格差了两行。

AI 成果最危险的地方，往往不是明显粗糙，而是“看起来已经完成”。质量检查的任务，是把主观满意变成可以追溯的证据，把未知和失败显式暴露出来。

> 验收不是问“它做完了吗”，而是证明“要求中的每一项现在都成立”。

## 32.1 质量由六个维度组成

不同成果可以共用六个基本维度：

| 维度 | 核心问题 |
| --- | --- |
| 正确性 | 数字、事实、逻辑和行为是否正确？ |
| 完整性 | 要求、材料和边界是否全部覆盖？ |
| 一致性 | 文件、版本、术语和数字是否相互一致？ |
| 可用性 | 目标读者能否打开、理解和实际使用？ |
| 可追溯性 | 结论与变化能否回到来源和证据？ |
| 安全性 | 是否泄露数据、越权或产生不可逆风险？ |

“没有发现错误”只覆盖正确性的一部分。一个数字全对却无法打开的演示不可用；一个内容完整却包含客户隐私的报告不安全；一个网站页面正常却没有保存用户数据，也没有达到需求。

验收标准应覆盖与成果有关的维度，不必机械填写所有项目，但不能只看文字流畅度。

## 32.2 在执行前定义验收

最晚在计划阶段写下“完成时什么必须为真”。如果等成果生成后才决定标准，人很容易根据已有结果降低要求。

好的标准具体、可观察、有范围。例如：

- 报告不超过五页，三项建议都有至少两处来源；
- 表格保留 1,240 条原始记录，主键无重复，总计与原表一致；
- 演示所有页面在 16:9 预览中无溢出，数字与最终表格一致；
- 网站在手机和桌面宽度可用，三个核心流程实际通过；
- 代码修改通过指定测试，diff 不含无关重构；
- 自动化在无新数据、来源失败和重复运行时行为符合说明。

避免“专业”“美观”“完整”“没有问题”这类无法单独判断的词。可以进一步定义：专业意味着用目标受众术语、不含未经支持的主张、关键决定在第一页。

## 32.3 建立五层验证

可靠验收应从输入一直检查到真实结果。

### 输入层

确认使用了正确材料、版本和日期，记录读取成功、失败与跳过。来源本身错误，后续加工再精确也无意义。

### 过程层

确认要求的步骤真实执行，例如搜索了当前资料、运行了检查、使用指定模板，没有偷偷替换成方便但不等价的方法。

### 内容层

核对事实、数字、逻辑、分类、语言和遗漏。这里既有自动规则，也有人类判断。

### 成果层

打开实际文件、页面或项目，检查格式、公式、布局、链接、交互和兼容。聊天中的文字预览不能代表最终文件。

### 外部状态层

如果任务涉及发送、发布、写入系统或部署，回到目标系统验证最终状态。Codex 说“已发送”不能替代收件箱、发布页面或记录系统中的证据。

每一层通过，才能支持下一层结论。

## 32.4 证据也有强弱

可以把验证证据按可靠程度排序：

1. **直接观察**：打开真实成果或外部系统确认；
2. **可重复检查**：测试、公式校验、链接检查和脚本输出；
3. **差异记录**：Git diff、版本比较、变更清单；
4. **来源映射**：结论对应原文位置或数据记录；
5. **过程说明**：Codex 描述自己做了什么；
6. **自我判断**：Codex 声称“已确认正确”。

越靠后越不能单独证明完成。过程说明帮助理解，但必须由文件、来源或检查结果支持。

证据还要与要求同范围。只测试一个页面不能证明整个网站兼容；抽查十行不能证明总计一致；某个子任务成功不能证明完整项目交付。

## 32.5 研究与文档怎样验收

研究报告重点检查来源覆盖、时效、引用准确和推断边界。

先建立“结论—来源”表：每个关键主张对应来源、位置、日期和证据性质。区分来源直接陈述、从数据计算、合理推断和建议。没有证据的判断不能伪装成事实。

检查是否只选择支持结论的材料，忽略矛盾来源；是否把不同年份、地区或口径的数据直接比较；是否引用搜索摘要而没有打开原页面；是否存在无法访问却仍被使用的文件。

文档还要检查受众和用途：结论是否在读者需要的位置，术语是否解释，行动项是否有负责人和日期。内容正确但结构让人无法决策，同样没有达到交付目标。

## 32.6 表格与数据怎样验收

数据质量检查至少包括：

- 原始与输出行列数量；
- 字段类型、单位和日期格式；
- 主键重复、缺失值和异常值；
- 清洗规则前后记录数量；
- 公式范围、总计和交叉核对；
- 筛选、隐藏行与工作表是否影响结果；
- 随机抽样能否追溯到原记录。

不要只看图表。先验证支撑图表的数据和公式，再检查图表标题、坐标、单位与筛选范围。

清洗操作要保留原始数据和转换日志。若 50 条记录被删除，说明规则与明细；不要用“无效数据”笼统解释。业务含义不清时标记待确认，而不是擅自填补。

## 32.7 演示与视觉成果怎样验收

演示同时有内容和视觉两套质量。

内容层检查故事线、每页目的、数字一致、来源和行动建议；视觉层检查文字溢出、遮挡、空白页、对齐、字号、颜色对比、图片清晰度和图表可读性。

必须渲染或打开实际演示，从第一页看到最后一页。只检查 Markdown 大纲不能发现版式问题。还要在目标屏幕比例和可能的导出 PDF 中查看。

图片生成要检查文字、手指、品牌元素、版权与人物授权。视频和音频则检查时长、字幕、同步、音量和完整播放。AI 生成素材应符合组织披露与使用政策。

## 32.8 网站与应用怎样验收

先把需求转成用户动作：“访客可以提交申请”“负责人可以按状态筛选”“刷新后记录仍存在”。逐条实际执行，而不是只确认页面出现。

至少检查：

- 桌面和手机主要宽度；
- 导航、链接、表单、错误提示和空状态；
- 登录前后、不同角色与权限；
- 数据创建、读取、修改、删除和持久化；
- 网络失败、重复提交和无效输入；
- 可访问性基本要求；
- 发布范围、域名、分析和隐私说明。

Sites 的 deployment URL 是生产部署，候选版本应在部署前完成检查。真正上线后再访问公开 URL，不能只看本地预览。

## 32.9 项目修改与代码怎样验收

代码质量不能只看测试变绿。先确认原问题可复现，再验证修改后的行为；查看完整 diff，排除无关重构、生成文件、密钥和用户已有修改。

检查可以分层：格式、类型、单元测试、集成测试、构建、真实操作和安全审查。项目规则决定具体命令，未运行的检查要说明原因。

`/review` 可以独立审查未提交变化、提交或分支，并给出带优先级的发现。审查者应报告可复现问题、文件位置和影响，而不是只提供风格偏好。

实现者与审查者最好在不同任务或角色中工作，减少沿用同一假设。修复审查问题后重新运行相关检查，并确认 diff 没有扩大。

## 32.10 自动化怎样验收

定时任务不能只手动成功一次。至少模拟：

- 正常有新数据；
- 没有新数据；
- 来源无法访问；
- 输入格式改变；
- 同一运行重复触发；
- 部分步骤成功、部分失败；
- 权限或认证过期；
- 达到停止条件。

检查它能否区分“无变化”和“失败”，写入是否幂等，重试是否有限，异常是否通知正确负责人。第一次上线后的几次运行必须人工抽查。

自动发送、删除或付款不应作为入门自动化验收对象。先验证只读检测和草稿生成。

## 32.11 抽样怎样才有意义

无法逐项人工检查时使用分层抽样，而不是随便看前几条。

从不同来源、日期、类别和风险等级中取样；额外检查异常值、边界值和 Codex 标记不确定的内容。随机样本帮助发现普遍错误，定向样本帮助发现高风险错误。

抽样只能支持相应范围的信心，不能证明所有记录正确。对总数、唯一性、公式和链接等可自动检查项目，应全量验证；对主观分类再抽样。

发现一项系统性错误时，不应只修样本，而要确定规则影响范围，重新处理全部相关数据。

## 32.12 独立审查与反向验证

让另一个任务以“找问题”为目标，而不是让原任务再次确认自己。提供原始要求、成果和审查标准，不必提供所有实现解释，避免被原思路带偏。

可以采用反向验证：从最终结论回到证据；从表格总计回到原记录；从网站行为回到需求；从 diff 回到原问题。

审查发现按严重度排序：

- **阻断**：数据泄露、错误发布、核心结果错误；
- **高**：会改变决定或主要用户行为；
- **中**：影响完整性、可维护性或部分用户；
- **低**：不影响结果的局部改进。

不是所有建议都必须接受。要求证据，区分事实错误、风险和品味差异。

## 32.13 验收报告的最小格式

```text
成果：
版本与位置：
验收范围：

已通过：
- 要求 / 检查方法 / 证据

未通过：
- 问题 / 影响 / 建议处理

未验证：
- 项目 / 原因 / 需要谁确认

来源与数据截止日：
实际运行的检查：
尚未执行的外部行动：
最终决定：接受 / 有条件接受 / 退回修改
```

“未验证”不是失败的同义词。明确缺口比虚假的全通过更专业。最终接受决定应由有责任的人作出。

## 32.14 一个可复制的审查提示

> 按原始需求独立验收当前成果，不要假设创建者的完成说明正确。分别检查正确性、完整性、一致性、可用性、可追溯性和安全性。先核对输入版本与读取范围，再检查内容和实际文件；运行适用的全量检查，对主观内容做分层抽样。每个发现给出证据、影响和严重度；无法验证的项目单列。只审查，不修改、不发送、不发布。

预期成果是带证据的验收报告。检查审查范围是否覆盖原要求，而不是只覆盖容易自动测试的部分。

## 32.15 常见误区

**Codex 说检查过就算证据。** 需要实际来源、输出或测试记录。

**抽查没有错误代表全部正确。** 抽样信心受样本设计限制。

**自动测试通过代表需求完成。** 测试可能没有覆盖真实目标。

**视觉好看代表演示可用。** 数字、来源和故事线同样重要。

**审查意见都要照做。** 应根据证据、影响和范围判断。

## 32.16 本章小结

质量验收覆盖正确性、完整性、一致性、可用性、可追溯性与安全性，并从输入、过程、内容、成果和外部状态逐层验证。直接观察和可重复检查比自我说明更有证明力。

> 真正的完成，不是没有人提出问题，而是每项要求都有足够证据支持，剩余未知也被清楚记录。

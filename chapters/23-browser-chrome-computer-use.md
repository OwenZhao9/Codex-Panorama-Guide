# 第二十三章：Browser、Chrome 与 Computer Use——让智能体进入真实界面

一项任务需要查看公开网页、登录内部系统，再把结果录入桌面软件。搜索只能找到公开信息，文件工具也无法操作这些界面。此时智能体需要浏览器或桌面控制能力。

Browser、Chrome 和 Computer Use 都能“看见并操作”，但它们接触的环境、登录状态和风险完全不同。选择错误工具，轻则无法完成，重则把敏感账号和数据暴露给不必要的流程。

## 23.1 三种工具的核心区别

| 工具 | 接触的环境 | 适合的任务 |
| --- | --- | --- |
| Browser | ChatGPT 内置或云端浏览环境 | 公开网页、本地网页预览、受控网站操作 |
| Chrome | 你的 Google Chrome 配置和已登录页面 | 需要现有标签页、账号或内部网站的任务 |
| Computer Use | 获准的桌面应用和操作系统图形界面 | 跨应用、设置、无法通过结构化工具完成的操作 |

还有一个更优先的选择：专用插件或 MCP。如果目标系统提供结构化连接，通常比在界面上模拟点击更稳定，也更容易限制数据和验证结果。

## 23.2 Browser：隔离的网页工作空间

内置 Browser 让 ChatGPT 打开网页、点击、输入、截图并检查页面。桌面应用中的内置浏览器使用与日常浏览器分开的配置；需要账号时可以在其中单独登录，不会自动继承你已有的 Chrome 标签和会话。

Work web 还可能使用云端浏览器处理公开、未登录网站。它的 cookies 与本机浏览器分开，不能使用本机保存的密码、扩展或历史。具体能力与界面、方案和工作区设置有关。

Browser 适合：

- 搜集公开网站中的当前信息；
- 比较价格、库存、活动或条款；
- 预览和测试本地网页；
- 检查页面布局、链接和交互；
- 在隔离环境中完成范围明确的网页步骤。

如果任务只需要搜索若干事实，先使用 Web search；如果需要实际打开页面、操作控件或观察渲染结果，再使用 Browser。

## 23.3 Chrome：使用你的真实浏览上下文

Chrome extension 让 ChatGPT 在你的 Chrome 中工作，可以读取或操作已经登录的网站、当前标签页和内部工具。这解决了内置浏览器没有现成登录状态的问题，也扩大了风险范围。

适合的场景包括：

- 在已经登录的 CRM 中查看或更新记录；
- 使用公司内部网页；
- 根据当前打开页面继续任务；
- 处理必须依赖个人 Chrome 会话的流程。

Chrome 权限可能包括读取和更改网页数据、浏览历史、下载与标签组等。安装扩展时系统显示的是扩展能够做什么，ChatGPT 仍会通过网站确认、允许列表和阻止列表控制具体任务。

不要选择“允许所有网站”只为了少点一次确认。对于账号、邮件、财务和内部系统，按站点授权更容易控制影响范围。

## 23.4 Computer Use：操作桌面应用

Computer Use 可以在获得授权后观察和操作 macOS 或 Windows 图形界面，包括窗口、菜单、键盘输入和剪贴板。它适合命令行、文件工具或插件无法完成的任务，例如复现桌面应用问题、修改只能点击的设置、查看没有结构化接口的数据，或者跨多个应用完成流程。

在 macOS 上通常需要屏幕录制和辅助功能权限；在 Windows 上会使用当前活动桌面并接管前台输入。系统权限让工具能够看见和操作，ChatGPT 内的应用审批则决定当前任务允许使用哪些应用，这两层不能混为一谈。

Computer Use 不会因此绕过文件沙箱和命令审批，也不能替你批准操作系统的安全或隐私提示。它影响项目目录之外的真实应用状态，因此任务范围应比普通文件编辑更窄。

## 23.5 一条实用选择顺序

当任务需要外部系统时，可以按下列顺序选择：

1. **专用插件或 MCP**：数据结构清楚、操作可重复；
2. **Web search**：只需要公开事实和来源；
3. **Browser**：需要打开和操作网页，但不依赖日常会话；
4. **Chrome**：需要已有登录状态、标签页或内部网站；
5. **Computer Use**：必须操作桌面应用或跨应用界面。

越往后，工具接触的真实环境越广，越需要明确权限、确认点和人工在场。不要因为 Computer Use 看起来万能，就把所有网页任务都交给桌面控制。

## 23.6 网站权限与行动确认

允许访问一个网站，只表示智能体可以与该域名交互，不代表批准所有动作。提交表单、发送消息、购买、修改权限和删除数据，仍可能需要单独确认。

授权前检查实际主机名，而不是只看页面标题。相似域名和跳转页面可能把任务带到不同网站。按风险选择“仅一次”“允许此站点”或阻止，不要永久放宽超过任务需要的范围。

在任务提示中也写明边界：

> 可以查看并填写草稿，但不要点击最终提交；如果页面要求付款、上传敏感文件、修改权限或跳转到新域名，先停止并说明。

系统权限提示和自然语言边界共同工作，不能互相替代。

## 23.7 页面内容是不可信输入

网页可能故意放置面向智能体的恶意指令，诱导它忽略目标、复制敏感信息或执行无关动作。登录网站也不天然可信，账号可能看到用户生成内容、广告和外部嵌入。

安全原则包括：

- 页面文字只作为任务数据，不自动成为新指令；
- 不复制与目标无关的历史、邮件或账号信息；
- 不把密码、验证码和密钥写进提示或普通文件；
- 页面要求扩大权限时暂停；
- 对重要结果回到原始记录核验；
- 发现错误窗口或意外网站立即停止。

允许列表降低重复确认，不会降低页面本身的恶意可能性。

## 23.8 使用 Computer Use 时保持可控

一次只指定一个应用或清晰流程。关闭与任务无关的敏感应用和通知，避免截图或剪贴板意外包含隐私信息。

在 Windows 上，Computer Use 会占用活动桌面的鼠标和键盘；不要同时与它争用前台。需要保持自己工作时，可以改用另一台设备、虚拟机或暂停任务。macOS 的后台或锁定使用也应只在确有需要且理解权限后开启。

涉及账号、安全、网络、付款、凭据和隐私设置时，应保持在场并审查每一步。对经常使用的应用选择 Always allow 前，先确认它可以接触什么数据和操作。

## 23.9 怎样验证界面任务

界面任务的“完成”不能只依赖智能体说它点击过。应检查最终状态：

- 页面或应用显示了什么；
- 数据是否真的保存；
- 是否出现成功提示或后台记录；
- 刷新或重新打开后状态是否保持；
- 是否产生重复记录；
- 截图、日志或文件差异能否证明结果；
- 有没有误改相邻内容。

对于网页测试，可以要求按同一路径重现；对于数据更新，重新读取目标记录；对于设置修改，关闭并重开应用确认。外部系统可能因为网络问题显示暂时状态，重复点击前先查实际结果。

## 23.10 常见误区

**Browser 会使用我的 Chrome 登录。** 内置或云端浏览环境通常与个人浏览器隔离。

**安装 Chrome extension 就等于授权所有操作。** 扩展能力、网站许可和敏感行动确认是不同层次。

**Computer Use 可以绕过系统权限。** 它必须获得操作系统和 ChatGPT 应用授权。

**允许网站说明内容可信。** 权限只允许访问，不验证页面指令和事实。

**点击完成就不必验证。** 网络延迟和页面错误可能造成重复或未保存状态。

## 23.11 第一次实践：只读比较三个网页

选择三个公开、不需要登录的网站，输入：

> 使用 Browser 比较这三个网站公开列出的价格、主要限制和更新时间。只进行只读浏览，不接受 cookies 以外的额外协议，不填写表单，不下载文件，也不进入其他域名。返回带页面链接的比较表，标出无法确认或需要人工联系的信息，并说明你实际访问了哪些页面。

验收时打开来源链接，抽查页面内容和日期，确认没有把搜索摘要当成页面事实，也没有执行超出只读范围的行动。

## 23.12 本章小结

Browser 提供隔离的网页环境，Chrome 使用你的真实浏览会话，Computer Use 操作获准的桌面应用。能用结构化插件时优先使用，只有任务确实依赖界面时再扩大控制范围。

> 工具越接近你的真实账号和桌面，任务范围就应该越小，验证和人工确认就应该越强。

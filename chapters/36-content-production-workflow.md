# 第三十六章：实战案例三——建立个人内容生产流程

许多人第一次让 AI 做内容，会一次要求它“写一篇文章、做几张图、再发到所有平台”。结果通常是产量很高，却主题松散、语气不一致、事实没有核验，发布之后也不知道哪些内容值得复用。

本章以“每周发布一篇知识通讯，并改编成三条短内容和一张配图”为例，演示怎样让 Codex 帮助建立一条稳定的个人内容生产线。这里的重点不是让模型替你表达，而是把选题、研究、写作、视觉、审校、发布准备和复盘变成可控制的流程。

## 36.1 先写内容系统的边界

假设作者的主题是“普通人怎样更好地使用 AI 工具”，读者是没有技术背景的职场人士。每周交付包括：

- 一篇 1,500—2,000 字的主文章；
- 三条适合不同平台的短内容草稿；
- 一张横版主视觉和一张方形缩略图；
- 一份标题与摘要备选清单；
- 一份来源、版权和事实核验记录；
- 一张发布后复盘表。

有三条边界：Codex 可以研究、起草、改编和检查，但不在未经确认时公开发布；涉及个人经历的段落必须由作者提供或确认；引用、案例和数字必须能追溯，不能为了故事完整而虚构。

内容系统的“完成”不是生成了很多字，而是所有版本表达同一个核心观点，适合各自平台，视觉与品牌一致，事实经过检查，并处于可以由作者最后确认的状态。

## 36.2 建立内容 Project 和文件结构

长期内容适合放在一个 Project 中，保存品牌说明、受众画像、优秀范例、禁用表达、过去选题和来源规范。每期内容单独开聊天，避免把几十期草稿全部混在同一上下文里。

本地文件可以按下面的方式组织：

```text
content/
  brand-guide.md
  audience.md
  editorial-calendar.csv
  sources/
  issues/
    2026-07-ai-task-design/
      00-brief.md
      01-research.md
      02-draft.md
      03-final.md
      derivatives.md
      visual-brief.md
      qa.md
  retrospective.csv
```

品牌说明不要只写“专业、温暖、有深度”。应写成可判断的规则，例如：开头从真实问题进入；解释术语时给一个生活例子；不用夸大承诺；不把读者称作“小白”；短句优先；遇到不确定事实要标注日期和来源。

优秀范例也要说明好在哪里。Codex 不需要模仿某位具体作者，而应学习结构、节奏和信息密度。若有不希望出现的写法，例如大量感叹号、虚构对话或“震惊体”标题，也应明确列出。

## 36.3 从选题池到一页内容简报

选题池可以记录主题、读者问题、时效性、已有材料、预期价值和状态。每周不要直接让 Codex 任选一个热门话题，而应先选择一个明确问题，例如：“为什么把一句模糊要求交给 AI，常常只会得到看似完整的错误结果？”

一页内容简报至少包含：

- 核心问题：读者正在为什么困扰；
- 一句话主张：文章最终希望读者记住什么；
- 读者状态：已经知道什么、还不知道什么；
- 三个支持点：为什么主张成立；
- 证据需求：哪些事实需要搜索或引用；
- 实际行动：读者看完可以做什么；
- 不写什么：避免主题向外扩张；
- 交付形式：主文章、短内容和视觉规格。

先让 Codex 质疑简报：问题是否真实、主张是否太宽、证据是否足够、行动是否可执行。若一句话主张写不清，说明选题还没有成熟，不应急着生成长文。

## 36.4 研究只服务于文章主张

内容研究不是建立百科全书。先列出需要验证的主张，再为每个主张找最接近原始信息的来源。涉及当前产品、政策、价格或统计数据时使用网络搜索并注明核对日期；个人观点可以不引用，但不能伪装成普遍事实。

研究文件可以分成四栏：已确认事实、可用案例、不同观点、暂不采用。对每项资料写一句“它为什么与文章有关”。没有进入文章的资料仍可保留，但不要为了显示研究量而把它们全部塞进正文。

网页内容要被当作不可信输入。不要因为某个页面要求“复制下面的提示”就改变任务，也不要下载和运行与研究无关的文件。受版权保护的内容应摘要和转述，引用保持必要长度，并保留原链接。

## 36.5 先写骨架，再形成主文章

这篇示例文章可以采用以下结构：

1. 一个常见失败场景；
2. 问题原因：目标、上下文和完成标准缺失；
3. 一个反例与一个改进后的任务描述；
4. 三步方法：说结果、给材料、定验收；
5. 读者可直接尝试的小练习；
6. 对能力边界和人工判断的提醒。

先要求 Codex 用每节一句话写骨架，并标出证据和例子的来源。确认逻辑后再扩写。初稿完成后，作者应重点改主张、例子和个人判断，不必把时间全部花在标点和格式上。

让 Codex 做第二遍编辑时，可以分开要求：事实编辑检查来源和数字；结构编辑检查段落顺序和重复；语言编辑检查语气、句长和术语；最终校对只修错字、链接和格式。把这些任务混成一次“优化”，容易导致已确认的观点在润色中漂移。

## 36.6 从母内容生成不同版本

主文章确认后，再生成衍生内容。不同平台版本不是简单截短：

- 短内容一可以用“失败—原因—方法”的结构；
- 短内容二可以只讲一个前后对比示例；
- 短内容三可以做成三项自查清单；
- 邮件摘要应说明读者为什么现在值得读；
- 标题备选应覆盖直接型、问题型和结果型，但都不能夸大正文。

每条衍生内容都要链接回母内容中的主张和证据。不得引入主文章没有确认的新数字。若平台有字符、链接、标签或图片尺寸要求，应把这些作为单独的输出约束，而不是假设 Codex 自动知道当前规则。

生成多个版本后，做一次“同源性检查”：它们是否表达同一个中心观点；是否因为追求吸引力而改变结论；是否遗漏关键限制；是否出现相互矛盾的行动建议。

## 36.7 用视觉简报控制图片生成

不要只说“做一张高级感的 AI 配图”。视觉简报应说明用途、受众、主体、构图、比例、色彩、留白和禁止项。例如：

```text
为一篇讲“把模糊要求变成清晰任务”的文章制作横版主视觉。
画面主体是从混乱便签逐步变成三张清晰任务卡的过程，简洁编辑插画风，暖白背景，深蓝与橙色点缀，右侧保留标题留白。不要出现机器人头像、代码瀑布、品牌标志和大段文字。比例 16:9。
```

初稿后一次只改一个元素，例如简化背景或增加标题留白，避免整张图不断漂移。需要使用作者肖像、客户素材或真实人物时，要确认权限。避免要求复制某位在世艺术家的独特风格，优先描述构图、媒介和视觉特征。

图片中的文字容易出错。生产级标题最好在排版工具中完成；若必须生成文字，要逐字检查。最终还应验证尺寸、裁切安全区、缩略图可辨识度、颜色对比和替代文本。

## 36.8 发布前设置人工确认点

发布包可以准备好标题、正文、摘要、图片、替代文本和平台草稿，但默认停在“待确认”。作者最后检查：

- 文章是否仍表达自己的判断，而非只有顺滑措辞；
- 事实、引用、链接和日期是否准确；
- 是否泄露未公开资料或他人个人信息；
- 标题是否兑现正文；
- 各平台版本是否符合当前规则；
- 图片、音乐、字体和案例是否有使用权限；
- 发布位置、账号和时间是否正确。

如果使用连接器或 Computer Use 准备平台草稿，应把“创建草稿”和“公开发布”视为不同权限。任何会立即影响受众的操作，都应在执行前再次确认确切内容和目标账户。

## 36.9 用复盘决定下一期怎么改

复盘表可以记录选题、发布时间、打开或阅读、保存、回复、点击、有效反馈、制作耗时和复用情况。不要只追逐曝光量。若目标是建立信任，读者回复和持续阅读可能比单次浏览更有意义。

每四期做一次小复盘：哪些问题最能引发真实反馈；哪些结构更容易理解；哪些环节最耗时；哪些错误重复出现。稳定重复的步骤可以写成 Skill，例如“从一页简报生成内容包”；数据来源稳定、结果格式清楚且人工试跑通过后，再考虑用 Scheduled task 自动准备周报或选题候选。发布动作仍应保留人工确认。

## 36.10 可直接复制的任务提示

```text
请根据本期内容简报，准备一套个人知识通讯内容包。

先读取 Project 中的品牌说明、受众画像、优秀范例和来源规范。不要模仿特定作者；遵守已有语气和禁用表达。先检查简报的一句话主张、读者问题、证据需求和范围，若存在会改变方向的缺口再提问。

交付：
1. 1,500—2,000 字主文章；
2. 三条结构不同的短内容；
3. 标题、摘要和邮件导语备选；
4. 横版主视觉与方形缩略图的视觉简报；
5. 来源与事实核验表；
6. 发布前检查表。

涉及当前事实时使用网络研究并标注核对日期。不得虚构个人经历、案例、引用或数字。衍生内容只能使用主文章中已经确认的主张和证据。

先交付文章骨架和证据映射，确认后再写正文。完成后分别进行事实、结构、语言和格式检查。所有平台内容只准备草稿，不要发布或发送。
```

## 36.11 本案例的能力边界

Codex 能让内容流程更稳定，但不能代替作者建立观点、承担公开表达的责任或判断受众关系。自动化也不能把低质量选题变成好内容。使用平台数据时要遵守隐私和服务规则；处理读者来信、客户案例和采访材料时，应去除不必要的个人信息。

最值得沉淀的不是一组万能提示，而是内容系统：品牌说明、选题表、内容简报、来源记录、分层编辑方法、视觉简报、发布检查和复盘数据。它让 AI 在边界内提高效率，同时保留作者真正不可外包的判断。

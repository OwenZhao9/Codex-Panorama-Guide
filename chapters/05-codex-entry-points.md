# 第五章：Codex 的使用入口

你可以在网页中让 AI 研究资料，也可以在桌面应用中操作本地项目；开发者可能更习惯终端或代码编辑器，同一项云端任务还可以在离开电脑后继续运行。

这些入口连接的是同一套 Codex 能力，却处在不同工作环境。选择入口时，最重要的不是哪个看起来专业，而是真实材料在哪里、任务要使用什么工具、你希望怎样检查结果。

> 入口选择的本质，是让智能体尽量靠近工作对象，同时保留合适的控制方式。

## 5.1 先看一张入口地图

截至 2026 年 7 月 18 日，普通读者最常遇到以下入口：

| 入口 | 最接近什么 | 适合什么 |
| --- | --- | --- |
| ChatGPT 网页 | 在线对话、上传文件、连接服务与云端能力 | 问答、Work、在线研究、Sites、托管任务 |
| ChatGPT 桌面应用 | 本地文件、应用、浏览器和项目 | 日常工作、本地 Codex、预览与交互执行 |
| Codex CLI | 终端、脚本和本地仓库 | 命令行项目、自动化、可重复技术流程 |
| Codex IDE Extension | 正在编辑的文件和代码 | 边看边改、解释选区、项目开发和审查 |
| Codex 云端任务 | 隔离容器和指定仓库版本 | 后台执行、独立变更、并行与可复现环境 |
| 移动端与集成 | 随时查看、跟进或从协作工具触发 | 轻量跟进、云端任务、通知和团队协作 |

并非每个账号都同时拥有所有入口。方案、地区、设备、工作区管理员和产品成熟度都会影响可用范围。以当前界面和官方文档为准。

## 5.2 ChatGPT 网页：最容易开始的入口

网页适合不依赖本机环境的工作。你可以使用 Chat 讨论，切换 Work 完成有明确结果的任务，上传文件，连接插件和外部服务，也可以进入 Sites 创建和管理在线项目。

网页端的优势是无需准备本地开发环境，适合研究、写作、文件分析、连接云端资料和托管任务。需要分享任务或在不同设备继续时，也比较自然。

它的边界同样清楚：网页不会自动看到你电脑上的任意文件夹，也不能凭一句“使用桌面最新版”访问本地资料。你必须上传文件、使用项目资料、连接服务，或把仓库提供给云端环境。

适合网页的提示例如：

> 使用我上传的四份政策文件，制作一份带来源的比较报告。只使用这些文件，所有日期按原文记录，无法确认的地方标为未知。完成后提供可下载文档，并列出未能读取的内容。

如果资料频繁变化，不要反复上传彼此冲突的版本；应明确哪个文件是当前版本，或通过受控连接来源读取。

## 5.3 ChatGPT 桌面应用：连接本地工作的中心

桌面应用把 ChatGPT、Work 和 Codex 带到本机环境。Work 可以在工具可用时使用本地文件、应用和浏览器；Codex 可以打开项目、查看文件差异、使用集成终端和 Git 工作树。

它适合以下情况：

- 材料存放在本地文件夹，不适合逐个上传；
- 需要创建并预览文档、表格或演示；
- 要操作本地项目、运行软件或检查网页；
- 需要 Browser、Chrome 或 Computer Use 等桌面能力；
- 希望在图形界面中查看任务、权限、差异和子任务。

本地能力更强，也意味着边界更重要。打开项目时选择最小必要目录，不要把整个个人主目录当作工作区；使用真实文件前先确认是否有备份或版本记录；对邮件、浏览器账号和桌面应用的操作保留确认点。

桌面应用还提供集成终端。它可以运行项目检查和 Git 命令，Codex 也能读取终端输出。但终端不是必须由普通读者亲自操作的门槛；它只是让可验证流程有一个清晰执行环境。

## 5.4 Codex CLI：终端优先的本地入口

CLI 是 Command Line Interface，也就是命令行界面。它在终端中运行，适合已经使用命令行、脚本和 Git 的读者。

CLI 的优势是直接、可组合和易于重复。你可以在项目目录启动 Codex，让它读取文件、执行命令、运行测试和显示变化；也可以把稳定步骤接入脚本、持续集成或其他开发流程。

CLI 并不天然比桌面应用更强。它缺少某些图形界面和管理视图，例如不能独立管理 Sites 或 Scheduled，也不提供桌面 Browser 体验。相反，它擅长项目中可通过文件和命令表达的工作。

适合 CLI 的任务例如：

> 检查当前仓库的文档链接，只修复确定失效的相对链接。运行项目现有检查，显示修改 diff，不要提交。

不熟悉终端时，不必从 CLI 开始。先在桌面应用建立任务、权限和验收意识，再学习少量必要命令，通常更顺畅。

## 5.5 Codex IDE Extension：在编辑器旁边协作

IDE Extension 把 Codex 放进代码编辑器。它能利用当前文件、选区和工作区上下文，适合一边阅读项目一边解释、修改、测试和审查。

典型工作包括：解释不熟悉的代码、根据选中区域提出最小修改、实现明确功能、运行检查和审查当前分支。与复制代码到网页相比，它更接近真实项目，也更容易引用准确文件位置。

IDE 入口仍然受项目目录、沙箱和权限限制。编辑器打开了一个文件，不代表任务应该改整个仓库；选中了代码，也不代表模型知道完整业务背景。提示中仍要说明目标、范围和完成标准。

CLI 与 IDE Extension 共享许多本地配置和认证状态，适合在终端与编辑器之间切换。但 IDE 不包含所有桌面或网页功能：插件库、Sites 管理和 Scheduled 管理应在支持它们的网页或桌面入口中完成。

## 5.6 Codex 云端任务：把工作放进隔离环境

Codex 云端任务会在托管容器中检出指定仓库的分支或提交，根据环境配置安装依赖，然后执行任务。完成后返回回答和文件差异，你可以继续追问或进入协作流程。

它适合耗时较长、可以独立运行、需要与本地修改隔离的工作。例如调查大型仓库、执行一组测试、准备独立变更或并行处理多个互不依赖的方向。

云端不是本地电脑的镜像。它看不到没有提交、上传或连接的资料，也不会自动拥有个人应用登录状态。环境变量、Secret、网络访问和设置脚本有专门规则，应在需要时配置，而不是假设全部继承。

选择云端前确认：使用哪个分支或提交；设置脚本能否重建环境；执行阶段是否需要网络；结果以什么形式带回；有没有两个任务同时修改同一部分。

## 5.7 移动端与协作集成：作为补充入口

符合条件的账号可以在移动端查看或使用部分 Codex 与 ChatGPT 能力，也可以通过 GitHub、Slack 等集成触发或跟进特定流程。它们适合在离开主要工作环境时查看进度、回复问题、接收通知或处理云端协作。

移动端不应被假设为完整本地开发环境。需要访问电脑文件夹、运行本地工具、操作桌面应用或详细审查大量差异时，应回到桌面、CLI 或 IDE。

集成也不是自动获得全部权限。GitHub 能看到哪些仓库、Slack 能访问哪些频道，仍由账号授权、组织政策和连接设置决定。重要变更与对外发送应遵循团队原有审批流程。

## 5.8 ChatGPT 登录与 API key 登录

本地 Codex 客户端通常可以使用 ChatGPT 账号登录，也可以使用 OpenAI API key。两种登录方式对应不同的可用能力和计费体系。

使用 ChatGPT 登录时，模型、额度和云端功能取决于你的 ChatGPT 方案与工作区。使用 API key 时，CLI、SDK 或 IDE 等调用按照 API 组织、项目、可用模型和 token 计费；它并不自动带来 ChatGPT 云端任务、GitHub 代码审查或 Slack 等云端功能。

不要在提示、仓库或截图里公开 API key。认证信息应存放在产品支持的安全位置，并使用权限范围合适的组织与项目。团队环境中还要确认管理员要求。

普通读者不需要为了“更专业”而主动改用 API key。若现有 ChatGPT 方案已经满足任务，保持简单更容易管理；只有在程序化调用、共享自动化或独立 API 计费确有需求时再配置。

## 5.9 根据材料位置选择入口

一个实用判断顺序是：

1. **材料在哪里？** 网页和云端服务、本地文件、代码编辑器，还是 Git 仓库？
2. **任务要做什么？** 只读分析、创建文件、运行命令、操作网页，还是部署站点？
3. **需要持续多久？** 即时对话、交互修改，还是适合后台运行？
4. **怎样验收？** 阅读回答、打开文件、查看 diff、运行测试，还是访问网址？
5. **风险在哪里？** 本地隐私、网络、外部账号、共享分支或公开发布？

如果资料都已上传，只要报告，网页 Work 足够；资料在本地且要生成多个文件，桌面更合适；核心工作发生在代码和命令中，选择 CLI 或 IDE；任务需要隔离后台执行，考虑云端；最终要托管网站，进入 Sites。

## 5.10 不必同时学习所有入口

入门时选择一条最短路径即可。

非技术读者可以从 ChatGPT 网页的 Chat 与 Work 开始，再使用桌面应用处理本地文件；需要网站时学习 Sites。开发者可以从熟悉的 IDE 或 CLI 开始，再补充桌面审查和云端任务。

不要在第一次任务里同时安装 CLI、编辑器扩展、插件、MCP 和多个浏览器工具。入口越多，认证、权限和故障来源越多。先在一个环境里跑通“定义—执行—验证”，再增加真正需要的能力。

## 5.11 一个可复制的入口选择练习

列出你最常做的三项任务，并填写：材料位置、最终成果、必需工具、是否能后台运行、主要风险。然后提出：

> 根据这三项任务的材料位置、最终成果、工具、持续时间和风险，为每项选择首选 Codex 入口和一个备选。区分工作模式与工具；不要建议我一次安装所有入口。说明第一步最小配置，以及我应怎样验收首次任务。

把建议与真实环境对照。如果首选入口无法访问材料，或验收方式在该入口不可见，就需要调整。入口选择不是品牌偏好，而是工作条件匹配。

## 5.12 常见误区

**CLI 是能力最完整的入口。** CLI 擅长终端工作，但缺少部分图形、Browser、Sites 和管理界面。

**网页可以直接读取电脑文件夹。** 本地资料必须上传、连接或在本地入口中使用。

**云端就是远程控制我的电脑。** 云端在独立容器中运行，不自动继承本机状态。

**API key 登录等于拥有 ChatGPT 全部功能。** API 与 ChatGPT 的权限、计费和云端功能不同。

**入口越多，Codex 越强。** 多余入口只会增加配置和风险；按任务选择即可。

## 5.13 本章小结

网页靠近在线资料和托管能力，桌面应用靠近本地文件与图形工具，CLI 靠近终端，IDE 靠近正在编辑的项目，云端任务提供隔离和后台执行，移动端与集成负责补充跟进。

> 最合适的入口，是能够安全接触真实材料、完成必要行动，并让你方便验收结果的入口。

至此，第一篇建立了完整基础：从聊天机器人到智能体，理解 Codex 的任务结构、能力边界、工作模式和使用入口。下一篇将进入安装、配置与环境准备，把这些概念变成可以实际运行的工作环境。
